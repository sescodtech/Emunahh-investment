# Secure Documents Implementation

This revision adds a provider-controlled supporting-document workflow while keeping the main application form clean and professional.

## Public application
- Four-stage service-specific form remains the primary intake.
- Five distinct journeys: Education, Travel, Business, Personal Finance and Investment Services.
- After successful submission, a secure supporting-document option appears only when uploads are enabled.
- Secure upload links use a long random token; only its SHA-256 hash is stored.
- Upload links expire after 30 days and can be regenerated by authorised staff.
- Document requirements are service-specific rather than one generic list.

## Admin controls
Admin → Site Settings → Application document storage includes:
- Enable/disable uploads.
- Provider selector: Disabled / Cloudinary / Google Drive.
- Test Mode.
- Max file size.
- Allowed extensions.
- Cloudinary document folder.
- Google Drive folder ID.
- Provider configuration test.

## Test Mode
Test Mode exercises the complete workflow and records a labelled test document entry. Actual file bytes are intentionally not retained externally.

## Cloudinary
- Server-side protected/authenticated uploads.
- API secret remains in Supabase Edge Function secrets.
- Admin document downloads are proxied through the Edge Function after RBAC checks.

## Google Drive
- Server-to-server upload with a service account.
- Designed for a company-controlled/shared-drive folder.
- Drive files are not made public; admin downloads are proxied through the Edge Function.
